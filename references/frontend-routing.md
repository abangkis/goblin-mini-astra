# Frontend routing

Load when the task involves design direction, rendered UI, or interaction judgment. Use the current [model profiles](model-profiles.md) for model/effort selection.

The Coordinator owns routine design direction and visual judgment. Routine workers implement clear designs, responsive behavior, and states. Judge rendered desktop/mobile screens and the primary interaction, not code or build output alone.

Keep work with the Coordinator when its existing context makes direct execution efficient. Delegate a concrete complex implementation question to an investigative worker when needed; do not add automatic visual approval by another model.

For a specific visual or interaction gap that remains after a focused Coordinator revision, consider the capability-gap investigation profile. Give it the brief, rendered evidence, observed gap, and bounded question; accept a targeted correction rather than restarting the frontend. For consequential original direction or experience-wide interaction tradeoffs, the escalation profile can be selected directly. Both require the core escalation gate.

Frontend work or task size alone does not justify escalation. Compare accepted results, user clarification, retries, handoffs, and attributable usage before claiming one profile improves quality or speed.
